1. pg_subtrans とは何か

pg_subtrans は、各トランザクション（XID）に対してその親トランザクションの XID を 記録する「サブトランザクション・ログ」マネージャです。ネストしたトランザクション （SAVEPOINT や PL/pgSQL の例外ブロックなど）の実装を支える基盤の一つです。

  • メイントランザクションの親は InvalidTransactionId（=0）。
  • 各サブトランザクションは「直近の親」の XID を持つ。
  • この木は子→親方向にしか辿れない（親→子は辿れない）。
重要: pg_subtrans は pg_xact（コミット状態ログ）と違い、 クラッシュをまたいで保存する必要がありません。現在実行中のトランザクションについてだけ 覚えていれば十分なので、WAL を出力せず、起動時には現在アクティブなページをゼロで初期化します。 ディスク上のファイルは $PGDATA/pg_subtrans/ 以下にあります。

2. SLRU（Simple LRU）とは

pg_subtrans のような「XID をキーにした固定長エントリの巨大な配列」を、ディスク上のファイル群と 共有メモリ上の少数のページバッファとで橋渡しするのが SLRU（Simple Least-Recently-Used） バッファ管理機構です（src/backend/access/transam/slru.c）。 pg_xact・pg_subtrans・pg_multixact・pg_commit_ts・pg_serial・pg_notify などが同じ SLRU 基盤を共有します。

SLRU の特徴:

  • 論理的に巨大な配列を BLCKSZ（既定 8KB）単位のページに分割。
  • 共有メモリには少数のページスロットだけを置き、LRU で入れ替える。
  • ページが満杯（書き込みやアクセスで全スロット使用中）なら、最も古いスロットを追い出して再利用。
  • 各 SLRU は pageno % nbanks でバンクに分割され、バンクごとの LWLock で並行アクセスを許容。

3. ディスク上・メモリ上のレイアウト

pg_subtrans の各エントリは 4 バイト（親の TransactionId）です。各サイズは次のとおり。

単位サイズ / 個数由来（ソース）
1 エントリ4 バイト（親 XID）sizeof(TransactionId)
1 ページBLCKSZ = 8192 バイト → 2,048 エントリSUBTRANS_XACTS_PER_PAGE = BLCKSZ / 4
1 セグメント（ファイル）32 ページ = 256 KB → 65,536 XIDSLRU_PAGES_PER_SEGMENT = 32
1 バンク16 ページスロットSLRU_BANK_SIZE = 1 << 4

4. XID からページ・エントリへの対応

XID は次の単純な割り算でページ番号とページ内オフセットに変換されます。

pageno  = xid / SUBTRANS_XACTS_PER_PAGE;   /* = xid / 2048 */
entryno = xid % SUBTRANS_XACTS_PER_PAGE;   /* = xid % 2048 */

XID は 32 ビットで 0xFFFFFFFF でラップアラウンドするため、ページ番号も 0xFFFFFFFF / 2048 で、セグメント番号も 0xFFFFFFFF / 2048 / 32 でラップします。 古さの比較にはモジュラ演算（SubTransPagePrecedes()）を使い、ラップに対応します。

5. バッファとバンク（並行性）

共有メモリのページスロットは SLRU_BANK_SIZE（=16）スロットごとにバンクへ まとめられます。あるページがどのバンクに属するかは: 

bankno = pageno % ctl->nbanks;
lock   = &shared->bank_locks[bankno].lock;   /* SimpleLruGetBankLock() */

バンク単位で LWLock を分けることで、別ページへの同時アクセスがロック競合しにくくなります。 追い出し（victim 選択）もバンク内で LRU カウンタが最大のスロットを選びます。

6. 主要 API と使われ方

関数役割主な呼び出し元
SubTransSetParent(xid, parent) サブトランザクションの親を記録（書き込み）。同じ値の再設定は許容、別の有効値への変更は禁止。 AssignTransactionId()(xact.c)、リカバリ時の RecordKnownAssignedTransactionIds 系(procarray.c)、2相コミット復元(twophase.c)
SubTransGetParent(xid) その XID の親を 1 段だけ取得（読み取り専用）。 SubTransGetTopmostTransaction() 内部
SubTransGetTopmostTransaction(xid) 親を辿って最上位（トップレベル）XID を返す。 スナップショット可視性判定(snapmgr.c)、実行中判定(procarray.c)、ロック待ち(lmgr.c)、heapam.c など

書き込みパス: SubTransSetParent

pageno  = TransactionIdToPage(xid);
entryno = TransactionIdToEntry(xid);

lock = SimpleLruGetBankLock(SubTransCtl, pageno);
LWLockAcquire(lock, LW_EXCLUSIVE);

slotno = SimpleLruReadPage(SubTransCtl, pageno, true, &xid);   /* ページを確保 */
ptr = (TransactionId *) shared->page_buffer[slotno] + entryno;

if (*ptr != parent) {
    Assert(*ptr == InvalidTransactionId);
    *ptr = parent;                       /* 親を書き込む */
    shared->page_dirty[slotno] = true;   /* dirty に */
}
LWLockRelease(lock);

サブトランザクションが XID を割り当てられる瞬間（AssignTransactionId）に、 親が SubTransSetParent で記録されます。

なぜ「最上位」を引くのか: スナップショットには各バックエンドのサブ XID も 載りますが、その数には上限があり「あふれた（overflowed / suboverflowed）」場合はサブ XID リストが 省略されます。その状態であるタプルの XID が可視かを判定するには、pg_subtrans でトップレベル XID まで辿り直して判定する必要があります。これが pg_subtrans の最大の利用目的です。

7. 最上位トランザクションの探索

SubTransGetTopmostTransaction は親リンクを辿りますが、TransactionXmin より 前は辿りません（それ以前の情報は切り詰められている可能性があるため）。途中で打ち切っても 「実行中かどうか」の判定には十分、というのが設計上のポイントです。 

parentXid = previousXid = xid;
while (TransactionIdIsValid(parentXid)) {
    previousXid = parentXid;
    if (TransactionIdPrecedes(parentXid, TransactionXmin))
        break;                                   /* これ以上は辿らない */
    parentXid = SubTransGetParent(parentXid);

    /* 親は必ず子より前。そうでなければ破損 → 無限ループ防止のため ERROR */
    if (!TransactionIdPrecedes(parentXid, previousXid))
        elog(ERROR, "pg_subtrans contains invalid entry ...");
}
return previousXid;

9. 関連する設定パラメータ

パラメータ意味既定 / 挙動
subtransaction_buffers pg_subtrans 用の共有バッファ（ページスロット）数。 0 で自動調整: shared_buffers 1GB あたり 2MB、最大 8MB 相当。明示指定時は 16 〜 SLRU_MAX_ALLOWED_BUFFERS にクランプ。

バッファ数は SUBTRANSShmemBuffers() が決定し、SimpleLruAutotuneBuffers(512, 1024) を 用いて自動調整します。スロット数は必ず SLRU_BANK_SIZE（16）の倍数に丸められます。
